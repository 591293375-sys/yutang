# 3.0.0 猫咪喂食位置修复与验证

原先按固定距离安排猫的落脚点，未考虑各品种进食帧的嘴部位置；到达后还可能保留走路朝向。因此小体型英短可能背对食盆低头，大体型橘白的嘴也会停在猫粮旁边。

现在用 16 款猫的真实嘴部锚点，结合大小、胖瘦与进食微动计算停靠位置。猫先走到位、转向，再嗅闻、进食。双猫各有一个进食位；食盆在创建时确定位置与尺寸，进食期间不移动、不缩放。猫的对齐来自实际路径和落脚点，没有额外平移整张进食贴图。

## 已实际完成的验证

- 开发版 19 场景：16 款默认体型、英短 size 0.7/build 0.8、橘白 size 1.35/build 1.25，以及布偶/英短共用食盆。190 张原生时序截图，160 个进食嘴点均位于猫粮区域，最大嘴/目标接触点误差 0.829 CSS 像素。
- mac-arm64 正式包 3.0.0 的 6 场景：默认布偶/英短/橘白、上述两种体型及双猫。60 张原生时序截图，56 个嘴点检查通过，最大误差 0.755 CSS 像素。进食期间脚点漂移为 0，食盆位置和尺寸保持不变，未见背对食盆吃地面或嘴部明显悬空。
- 正式包通过实际 UI 切换「锦鲤池 → 赶海 → 猫咪庭院」，三个主题正常启动；主题选择持久化，猫咪 ID、品种和体型参数恢复。0 个页面错误。
- 项目单元测试 407/407、桌面窗口策略测试 5/5 通过。签名由发布流程执行 `codesign --verify --deep --strict` 并通过。

## 复现命令

在仓库根目录安装依赖，启动本地开发服务器：

```sh
pnpm install
pnpm dev --port 5188
```

保留服务器运行，在另一个终端执行全品种检查：

```sh
node electron/cat-feeding-smoke.cjs --all
```

默认不带 `--all` 为 6 个代表场景。若开发服务器端口不同，可设置 `VITE_DEV_SERVER_URL`。测试不需要额外安装 Sharp 或截图工具。

macOS Apple Silicon 正式包验证：

```sh
pnpm package:mac
node electron/cat-feeding-smoke.cjs --packaged
```

默认使用 `release/mac-arm64/浮生锦鲤池.app/Contents/MacOS/浮生锦鲤池`。如要验证另一份同版本桌面构建，可用 `CAT_PACKAGED_EXECUTABLE` 指定可执行文件。测试会断言实际应用版本与仓库 package.json 一致，并记录实际包哈希。

可独立运行逻辑和桌面策略测试：

```sh
pnpm test
pnpm test:desktop
```

## 测试方式与输出

Browser plugin not available；本次沿用项目的 Playwright/Electron 方式。脚本创建独立临时用户目录并验证其确实生效；不读取或修改用户存档，不关闭用户自己的应用。结束时退出测试实例、删除临时目录。

使用真实 `BrowserWindow.setContentSize(1600,900)` 与 `webContents.capturePage()`，没有使用 CDP viewport 或 Playwright screenshot。通过实际 UI「道具 → 食物 → 庭院」操作，保留靠近、嗅闻及连续八个进食时点。对游戏运行时仅作只读观测，不跳过行走路径或直接触发进食状态。

输出在 `work/cats/feeding-3.0.0/dev-3.0.0/` 或 `packaged-3.0.0/`，可通过 `CAT_FEEDING_OUTPUT` 更换输出根目录。包含逐帧截图、各场景 `*-sequence.png`、完整窗口 `full-window.png` 与 `feeding.json`。序列合图仅排列原生截图。报告结果 `CAPTURED` 表示自动断言与采图完成，仍需人工检查可见嘴部位置；本次交付已完成该人工检查。

## 实际限制

位置数值使用实际进食帧的嘴部几何，并以原生截图进行人工交叉检查。没有穷举每个品种的所有大小/胖瘦组合、每个庭院落点或全部屏幕尺寸。正式包实际验证平台为 macOS Apple Silicon；其他系统未实际验证。本次主题切换为启动和恢复检查，不替代原有两个主题的完整回归。没有重复本轮未改动的音频和 4K 性能矩阵。
