# 中央庭院四季变化（2.7.4）

背景仍以原有 1920 / 3840 / 6144 档庭院图为坐标基准，未生成或增加大图资源。原季节绘画继续负责外围树冠、花丛；新增 `ground-season.js` 负责中央石板和苔藓的季节材料，以及少量静态落物。

- 春：原苔藓位置变嫩绿，中央与边缘分布 44 组小花瓣。
- 夏：保持原图地面。
- 秋：苔藓转暖黄/枯草色，34 枚小落叶分散在石板区域。
- 冬：原苔藓团和石缝形成薄霜，石板接受清冷光线；活动区域的原边界、石板接缝仍清楚。
- 背景落物是静态地面细节，关闭空气粒子后仍保留。动态落花/落叶由独立 `season-effects.js` 管理。

## 坐标与清晰度

季节材料仅作用于同一场景 UV 下的石板区域。猫窝、水碗、台阶、爬架和暖石使用同一组设施排除区域。绘制不会改动任何设施或石板的位置。

材料采样遮罩最多 1920 像素宽，颜色通过 `multiply` / `screen` 运算直接作用于原始 4K / 6K 像素；不是把采样图当作覆盖图片放大。原生细纹的空间频率和位置保留，薄霜会有合理的对比度下降。静态花瓣、落叶在最终画布尺寸下绘制。背景只在季节/时间/分辨率改变时生成，不进入逐帧渲染循环。

夜间材料在已有夜景上合成，增亮遮罩只使用日间强度的 18%，避免中央地面恢复正午亮度。此次没有替换或提高此前夜景原画的真实分辨率。

## 实际验证

独立 Electron 临时 profile 下直接运行当前 `courtyardBackground(3840, season, time)`，四季白天及四季夜晚均生成成功，页面错误为 0。已人工查看完整春/冬场景、秋/冬夜景、四季中心对照，以及 1:1 原生 4K 局部细纹。

关闭动物和粒子影响的纯背景中心区域，相对夏季的 RGB 平均绝对差：春 4.80、秋 10.66、冬 23.20；差异超过 8 的像素占比分别为 15.4%、45.0%、99.7%。这些数字说明中心已发生变化，不替代人工画面检查。

本次开发机 3840 背景完整生成（含已缓存/首次素材加载）约：春 380ms、秋 210ms、冬 226ms。此为单次生成耗时，不是每帧成本。

`node --test tests/cats-ground-season.test.js tests/cats-season-ground.test.js tests/cats-environment.test.js`：11 / 11 通过。覆盖合法地面与设施排除、材料变化、静态落物稳定分布、原生细节对比保留、夜间增亮限幅及动态粒子规则。
