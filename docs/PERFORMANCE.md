# 1.1 性能与 4K 验证

2026-09-27，本机 Apple M5、macOS 26（Darwin 25.6）、Electron 37.10.3、GPU / Canvas 加速开启、60 Hz 内置屏幕。所有测试使用隔离的用户目录，没有重置使用者的设置或自绘锦鲤。

## 原因与修复

原版在每帧绘制每尾鱼影时对主 Canvas 设置 `filter = blur(4px)`。在 3840×2160 画布上，这些命令会把大量工作推到异步 GPU 光栅阶段。仅测 JS 绘制函数时间（低于 1 ms）遗漏了实际帧调度卡顿。

相同 4K / 24 尾秋日晴天场景，连续采样 5 秒：原版 **4.69 FPS**，p95 帧间隔 **366.7 ms**；实验性跳过鱼影模糊后 **51.64 FPS**，再去掉背景 / 面板滤镜后 **59.00 FPS**。对应原始记录见 `performance/performance-before.json`。

正式修复把柔和阴影预绘到 288×144 的小纹理，每尾鱼每帧只做一次 `drawImage`。界面用半透明颜色和渐变替代动态背景模糊；昼夜用独立颜色叠层，锦鲤骨架、鳞片、游动、投食、自绘纹理变形均保留。标准模式限制 60 FPS，并为画布加入约 829 万像素的上限，避免误建 8K 表面。

## 场景压力测试

每项预热 1–1.5 秒，采样至少 5 秒；同时记录真实 rAF 帧间隔及引擎实际执行绘制次数。测试段不截图、不读取像素。绘制频率有窗口边界误差，略高于 60 的值不表示突破 60 FPS 限制。

| 场景 | 实际画布 | 绘制 FPS | p95 帧间隔 | >33.5 ms 慢帧 |
|---|---|---:|---:|---:|
| 秋日晴天 / 24 尾 | 3840×2160 | 59.6 | 17.1 ms | 0 |
| 春季雨天 / 24 尾 | 3840×2160 | 59.4 | 17.6 ms | 0 |
| 夏季夜景 / 24 尾 | 3840×2160 | 60.0 | 16.8 ms | 0 |
| 冬季雪天 / 24 尾 | 3840×2160 | 59.0 | 17.6 ms | 0 |
| 秋季雾天 / 24 尾 | 3840×2160 | 59.8 | 17.3 ms | 0 |
| 雾天投食 / 36 尾（含 12 尾自绘纹理） | 3840×2160 | 60.2 | 16.7 ms | 0 |

## 打包桌面应用

`electron/packaged-smoke.cjs` 对正式 `.app` 独立测试，两个状态各连续采样 10 秒：

- 窗口：3840×2160 / 24 尾，60.00 FPS，p95 16.8 ms，0 个 >33.5 ms 慢帧。
- 原生桌面层：随本机显示器实际分辨率 3420×2214 / 24 尾，60.00 FPS，p95 17.4 ms，0 个 >33.5 ms 慢帧。
- 四张季节 PNG 在应用包内解码后均为 3840×2160；实际背板尺寸、画面持续变化、桌面层、不抢焦点和控制恢复均通过。
- 签名校验通过，版本号 1.1.0。39 项逻辑 / 渲染回归测试与 4 项桌面安全 / 坐标测试通过。

原始记录：`performance/packaged-smoke-4k.json`。

## 分辨率边界

背景文件经 Image Gen 重绘，再从生成器实际返回的 1672×941 重采样为 3840×2160；不把重采样当作原生 4K 细节。锦鲤和动态粒子是实时绘制；显示器与窗口决定实际像素尺寸，小窗口不额外浪费 GPU 超采样。标准模式最大 3840×2160 等量像素；超宽与竖屏保持比例。4K 显示器使用其原生分辨率，Retina 1080p 的 backing buffer 是 3840×2160。节能模式最大 1920×1080 等量像素 / 30 FPS。

## 复现

```sh
pnpm dev
# 另一个终端（使用真实 Electron GPU，不用无头浏览器）
pnpm test:performance
# 打包后验证，不依赖 Vite
node electron/packaged-smoke.cjs
```

开发性能脚本将记录输出到项目 `work/`，会自动关闭自己的测试实例并移除自己创建的临时配置目录。打包检测需要本机能达到 45 FPS，否则会明确失败；请结合机器性能判断。
